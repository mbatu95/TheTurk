# ROS2 Turtlesim — Communication Demo

## 1. Install Turtlesim

```bash
apt update
apt install ros-jazzy-turtlesim
```

Check the installation:

```bash
ros2 pkg executables turtlesim
```

---

## 2. Start Turtlesim

```bash
export DISPLAY=:12
ros2 run turtlesim turtlesim_node
```

This starts the Turtlesim node and opens the simulator window.

---

## 3. Check the Running Nodes

```bash
ros2 node list
```

Look for:

```text
/turtlesim
```

Inspect it:

```bash
ros2 node info /turtlesim
```

This lets us see the Topics, Services and other ROS interfaces provided by the node.

---

# TOPICS

## 4. List Available Topics

```bash
ros2 topic list
```

Important Turtlesim topics include:

```text
/turtle1/cmd_vel
/turtle1/pose
```

---

## 5. Inspect the Velocity Command Topic

```bash
ros2 topic info /turtle1/cmd_vel
```

Check its message type:

```bash
ros2 topic type /turtle1/cmd_vel
```

Expected:

```text
geometry_msgs/msg/Twist
```

---

## 6. Inspect the Twist Message

```bash
ros2 interface show geometry_msgs/msg/Twist
```

This shows the structure of the message used to command the turtle's velocity.

---

## 7. Publish a Velocity Command

```bash
ros2 topic pub --once /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0}, angular: {z: 1.0}}"
```

The CLI acts as a publisher.

The turtle should move forward while turning.

---

## 8. Publish Continuously

```bash
ros2 topic pub --rate 10 /turtle1/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 1.0}, angular: {z: 0.5}}"
```

The velocity command is now published at 10 Hz.

Stop it with:

```text
Ctrl + C
```

---

## 9. Read the Turtle Pose

```bash
ros2 topic echo /turtle1/pose
```

The CLI acts as a subscriber.

You should see values such as:

```text
x
y
theta
linear_velocity
angular_velocity
```

---

## 10. Check the Pose Publishing Frequency

```bash
ros2 topic hz /turtle1/pose
```

This shows approximately how frequently pose messages are being published.

---

# SERVICES

## 11. List Available Services

```bash
ros2 service list
```

Turtlesim provides services such as:

```text
/clear
/reset
/spawn
/kill
/turtle1/set_pen
/turtle1/teleport_absolute
/turtle1/teleport_relative
```

---

## 12. Inspect the Spawn Service

```bash
ros2 service type /spawn
```

Expected:

```text
turtlesim/srv/Spawn
```

Inspect its request and response:

```bash
ros2 interface show turtlesim/srv/Spawn
```

---

## 13. Spawn a Second Turtle

```bash
ros2 service call /spawn turtlesim/srv/Spawn "{x: 2.0, y: 2.0, theta: 0.0, name: 'turtle2'}"
```

A second turtle should appear.

---

## 14. Check the Topics Again

```bash
ros2 topic list
```

Now you should also see topics belonging to `turtle2`.

For example:

```text
/turtle2/cmd_vel
/turtle2/pose
```

---

## 15. Move Turtle2

```bash
ros2 topic pub --once /turtle2/cmd_vel geometry_msgs/msg/Twist "{linear: {x: 2.0}, angular: {z: 1.0}}"
```

We are using the same message type but publishing to a different Topic.

---

## 16. Kill Turtle2

Check the service type:

```bash
ros2 service type /kill
```

Inspect the interface:

```bash
ros2 interface show turtlesim/srv/Kill
```

Call the service:

```bash
ros2 service call /kill turtlesim/srv/Kill "{name: 'turtle2'}"
```

`turtle2` should disappear.

---

## 17. Teleport Turtle1

Check the interface:

```bash
ros2 interface show turtlesim/srv/TeleportAbsolute
```

Call the service:

```bash
ros2 service call /turtle1/teleport_absolute turtlesim/srv/TeleportAbsolute "{x: 5.5, y: 5.5, theta: 0.0}"
```

The turtle should immediately move to the requested position.

---

## 18. Clear the Drawing

```bash
ros2 service call /clear std_srvs/srv/Empty "{}"
```

This clears the lines drawn by the turtles.

---

## 19. Reset Turtlesim

```bash
ros2 service call /reset std_srvs/srv/Empty "{}"
```

This resets the simulation.

---

# TELEOP

## 20. Control the Turtle With the Keyboard

Open another terminal:

```bash
ros2 run turtlesim turtle_teleop_key
```

Use the arrow keys to control the turtle.

While driving, open another terminal and watch:

```bash
ros2 topic echo /turtle1/cmd_vel
```

Now you can see the velocity messages generated by the teleop node.

---

## 21. Inspect the Teleop Node

```bash
ros2 node list
```

Then:

```bash
ros2 node info /teleop_turtle
```

This shows that the teleop node publishes velocity commands.

---

# RQT GRAPH

## 22. Visualize the System

```bash
export DISPLAY=:12
rqt_graph
```

With Turtlesim and keyboard teleop running, the ROS graph should show the communication between the nodes.
